# 0005 — Локализация V1.3: English по умолчанию, per-app locale, настраиваемая цель калорий

Статус: Accepted, 2026-10-08

## Контекст

V1.2 имела только русский UI и жёстко заданную дневную цель 2300 ккал
(`TodayTargets.CALORIES`). V1.3 добавляет два пользовательских изменения:
полноценную English-локализацию с выбором языка в настройках и
настраиваемую дневную цель калорий.

Требования к локализации: English — язык по умолчанию (fallback для
неподдерживаемых системных языков), русский — локализованный набор
ресурсов; выбор языка через стандартный Android-механизм, без
`if (locale)`-переводов в коде.

Ограничения: без архитектурного рефакторинга, без новых фреймворков
(Hilt/Room/DataStore), API-контракт Mealie не меняется, теги/релизы не
трогаются.

## Решение

**Ресурсы.** `values/strings.xml` — English (default/fallback),
`values-ru/strings.xml` — русский. В коде нет пользовательского текста:
все строки берутся через `stringResource`/`pluralStringResource`.
`localeFilters = ["en", "ru"]` в `androidResources`.

**Выбор языка — стандартный AndroidX per-app locale API.**
`AppCompatDelegate.setApplicationLocales(LocaleListCompat)` + сервис
`AppLocalesMetadataHolderService` с `autoStoreLocales=true` (хранение
выбора на API ≤ 32; на Android 13+ хранит фреймворк). Поскольку этот API
требует `AppCompatActivity`, `MainActivity` переведён с
`ComponentActivity` на `AppCompatActivity`, а тема приложения — с
`android:Theme.Material.*` на `Theme.AppCompat.*` (иначе
`AppCompatDelegateImpl.createSubDecor()` бросает
`IllegalStateException: You need to use a Theme.AppCompat theme`).
Значение языка — три варианта: System / Russian / English.

**Цель калорий.** Хардкод `TodayTargets` заменён на `DailyTarget`
(диапазон 500..10000, дефолт 2300 для совместимости). Значение хранится
в существующем `SettingsStore` (SharedPreferences) и публикуется как
`StateFlow`; `TodayViewModel.updateTarget()` применяет его к прогрессу
экрана «Сегодня».

**Форматтеры.** `DurationFormatter`, `NutritionFormatter`,
`QuantityFormatter` были захардкожены на русский («ч/мин», «ккал/г»,
запятая-разделитель). Теперь они не содержат собственных EN/RU-литералов:
клиентские метки (единицы «ккал/г/кг/л», «ч/мин») берутся из Android
ресурсов через необязательный `Context`, а десятичный разделитель следует
активной локали (`ru` → запятая, иначе точка). Ядро форматирования
параметризовано языком и рендерером метки, поэтому тестируется без
Robolectric. Токены сопоставления единиц Mealie (наборы «г/грамм/…»)
и имена категорий `TodaySlot.categoryName` («Завтрак», «Основное», …) — это
ключи данных, а не UI-текст (они сопоставляются с серверными категориями),
поэтому остаются как есть.

## Отвергнутые альтернативы

- **Собственный перевод через `if (locale)`** — требование ТЗ и источник
  ошибок; стандартный API даёт recreation и хранение «из коробки».
- **Перевести все форматтеры на `Context` без дефолта** — сломало бы
  юнит-тесты и не-UI вызовы; необязательный `Context` с параметризуемым
  по языку ядром сохраняет детерминизм и тестируемость.
- **Локализовать `TodaySlot.categoryName`** — сопоставление с серверными
  категориями сломалось бы при смене языка.

## Последствия

- Fallback для любого неподдерживаемого языка — English.
- Смена языка пересоздаёт Activity штатным способом; выбор сохраняется.
- `values-ru` должен содержать все ключи `values` (проверяется вручную;
  lint `MissingTranslation` не включён).
- Тема приложения привязана к AppCompat — это осознанная цена per-app
  locale на API ≤ 32.
