# 0004 — Экран «Сегодня»: nutrition Mealie и локальное состояние дня

Статус: Accepted, 2026-10-08

## Контекст

V1.2 добавляет стартовый экран «Сегодня» — конструктор дневного питания из уже
существующих рецептов Mealie: пользователь выбирает блюда по слотам приёмов
пищи, приложение суммирует калории/Б/Ж/У и позволяет менять число порций.

Два вопроса требовали решения до кода:

1. **Семантика nutrition в Mealie.** Значения пищевой ценности в API — это
   значения на **весь рецепт** или на одну порцию?
2. **Персистентность дня** без истории питания, Room, background worker'ов и
   offline-first архитектуры.

## Решение

**Nutrition — на весь recipe yield, без масштабирования.** Подтверждено
официальным FAQ Mealie: «the values you enter are static for the recipe and no
scaling is being done when changing Servings». Поэтому per-serving =
`value / recipeServings`, а вклад выбранного блюда =
`value / recipeServings * selectedServings` (при отсутствии recipeServings
считаем, что значение уже на порцию). Парсинг свободных строк (`"343"`,
`"343 ккал"`, `"12 g"`, `"3,4"`) вынесен в `domain/today/NutritionParser` +
`NutritionCalculator` с юнит-тестами; UI строки не парсит.

**День хранится в SharedPreferences** (`TodayStore` над узким `StringStorage`),
только текущий локальный календарный день в виде JSON: дата, slug, слот,
servings (Double). При смене локальной даты сохранённый набор читается как
пустой (date-чек при чтении; без alarm/worker). RecipeDetail в persistence не
хранится — после восстановления детали дозагружаются только для сохранённых
блюд.

## Отвергнутые альтернативы

- **Room / DataStore** — для одного дня и нескольких полей избыточно; в проекте
  уже есть SharedPreferences-хранилище настроек.
- **Хранить nutrition в persistence** — дублирование серверных данных и
  устаревание; источник истины остаётся Mealie.
- **История дней / календарь / графики** — вне scope V1.2.

## Последствия

- Смена servings блюда на сервере автоматически пересчитывает вклад (nutrition
  не кэшируется в дне).
- Нет истории и синхронизации между устройствами — это отдельная задача.
- Целевая калорийность 2300 ккал вынесена в `TodayTargets` — позже станет
  настройкой без правок экрана.
- Смена семантики nutrition в Mealie (масштабирование на сервере) — новый ADR,
  этот не переписываем.
