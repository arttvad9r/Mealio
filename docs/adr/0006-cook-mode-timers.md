# 0006 — Cook Mode: таймеры из текста шага

Статус: Accepted, 2026-10-08; Superseded by 0007 в части создания таймера и
завершения

## Контекст

Нужен режим готовки (Cook Mode) с контекстными таймерами. Mealie отдаёт шаги
как `RecipeStep` с полями `title`/`summary`/`text`, но **без структурированного
времени шага** — только общие `prepTime`/`cookTime`/`totalTime` рецепта.
Backend менять нельзя, новых endpoints добавлять нельзя.

## Решение

- Шаг инструкции в domain — `InstructionStep(title?, text)`: заголовок и тело
  хранятся раздельно (маппер больше не склеивает их в одну строку).
- Время шага извлекается локально чистой domain-функцией
  `CookTimerParser.parseSuggestions(text): List<TimerSuggestion>` (`domain/cook`):
  без Android/Compose, без regex в UI. Поддержаны EN/RU единицы (секунды/минуты/
  часы и сокращения), составные длительности («1 час 20 минут» → один таймер),
  простые диапазоны («6–8 минут» → `Range(from,to)`) и несколько независимых
  времён в одном шаге («5 минут, затем ещё 10 минут» → два `Single`).
- Составная длительность от независимых времён отличается по правилу «единицы
  строго убывают» (`1 час 20 минут`): два одинаковых юнита — уже отдельные
  таймеры.
- Диапазон не автозапускается: UI показывает два значения (`6 мин` / `8 мин`).
- Таймеры независимы: `ActiveTimer` хранит **абсолютный deadline** по монотонным
  часам (`SystemClock.elapsedRealtime()`), остаток всегда вычисляется из deadline
  (`remainingSeconds(now)`), а не декрементом. UI тикает раз в 250 мс, но не
  «уплывает» при recomposition, подвисании, смене шага или background/foreground.
- Deadline'ы зеркалятся в `SavedStateHandle` (`CookTimerViewModel`): краткий
  background с возможным убийством процесса сохраняет таймеры; reboot/force-stop
  вне scope V1.4.
- Завершение: визуальная отметка (`tertiaryContainer` + «Время вышло», не только
  цвет) и вибрация через `VibrationEffect` (permission `VIBRATE`, без runtime-
  запроса). Системных уведомлений и alarm-звука нет; foreground service не нужен.
- Cook Mode — не вкладка: полноэкранный composable поверх Recipe Detail,
  открывается кнопкой «Готовить» (видна только при ≥1 шаге), закрывается
  системным Back или «Готово» на последнем шаге.
- Экран готовки держится включённым штатным `FLAG_KEEP_SCREEN_ON` (без
  permissions), флаг снимается при выходе, если его не выставил кто-то другой.

## Отвергнутые альтернативы

- **Диапазон как один таймер по верхней границе** — ТЗ требует явного выбора
  двух значений и запрещает автозапуск для диапазона.
- **Таймер как декремент Int каждую секунду** — «уплывает» при лагах и смене
  шага; deadline-модель решает это без зависимостей.
- **WorkManager / системные будильники / foreground service** — избыточно для
  V1.4; фоновая доставка срабатывания не входит в задачу.
- **Regex «число + слово-единица» напрямую по тексту** — ловит температуры и
  количества («200 градусов»); токенизация с проверкой, что слово после числа
  действительно единица времени, отсекает мусор.
- **Отдельный экран управления таймерами** — не нужен: компактной области
  активных таймеров в Cook Mode достаточно, действий только «удалить» и
  «перезапустить».

## Последствия

- Подпись активного таймера безопасная и без NLP: «6 мин · шаг 2».
- Парсер консервативен (число + известная единица), иначе таймер не показывается
  вовсе; сложная семантика намеренно не разбирается.
- Словарь единиц локале-независим (регекс по кириллице/латинице), новых строк
  для распознавания не требуется; подписи кнопок — из ресурсов.
