# 0001 — Mealie как backend, а не кодовая база

Статус: Accepted, 2026-10-08

## Контекст

Есть официальный сервер Mealie (Python/FastAPI, v3.28.0) и его Go-порт
`mealie-go`. Нужен нативный Android-клиент для личного сервера Mealie.

## Решение

Mealio — **тонкий клиент**: самодостаточное Android-приложение, которое говорит
с сервером Mealie по HTTP/JSON (Retrofit + OkHttp + kotlinx.serialization).
API-контракт берём из локального `/openapi.json` (v3.28.0) как из источника истины.

## Отвергнутые альтернативы

- **Развивать `mealie-go`** — это сервер, а не клиент; не решает задачу UI на телефоне.
- **Переносить React Native архитектуру официального фронтенда** в Kotlin —
  чужеродные абстракции, лишний слой без пользы.
- **Свой backend-форк Mealie** — избыточно: сервер уже есть и работает.

## Последствия

- Странности Mealie API изолированы в `data/remote` + `data/mapper`; домен и UI
  от них не зависят.
- Версия API зафиксирована на v3.28.0; при апгрейде сервера сверять `/openapi.json`.
