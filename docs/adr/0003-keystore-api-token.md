# 0003 — Long-lived API-токен в Android Keystore

Статус: Accepted, 2026-10-08

## Контекст

Нужна устойчивая авторизация к self-hosted Mealie. Сервер поддерживает
`/api/auth/token` (form-urlencoded, выдаёт короткоживущую пару
access/refresh) и долгоживущие API-токены из настроек пользователя.

## Решение

V1 использует **long-lived API-токен**, который пользователь создаёт в Mealie и
вставляет в приложение. Токен шифруется ключом Android Keystore (AES/GCM,
`KeyGenParameterSpec`) и хранится в `SecureTokenStorage`; в открытом виде нигде
не персистится.

## Отвергнутые альтернативы

- **Логин/пароль + refresh-loop** — надёжный refresh заменяет вставленный
  токен на короткоживущий, ломая OIDC/SSO-сценарии; плюс пришлось бы хранить
  пароль. Лишняя сложность для V1.
- **Токен в обычных SharedPreferences** — открытый текст, недопустимо.

## Последствия

- Пользователь один раз создаёт токен в веб-интерфейсе Mealie.
- Данные исключены из cloud-backup и device-transfer
  (`data_extraction_rules.xml`) — токен не утечёт в бэкап.
- Смена схемы авторизации в будущем — новый ADR, этот не переписываем.
